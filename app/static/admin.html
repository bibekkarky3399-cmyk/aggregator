Providers

                            

                              
REST airline · JSON POST

                              
Agency · SOAP XML

                              
Custom partner · HTTP

                            

                          

                        

                        
Juniors: the aggregator is an adapter layer. Your product only learns one shape; providers keep their own APIs.

                      

                    


                    

                      

                        

                          POST = HTTP method
                          Headers = metadata
                          Body = JSON payload
                          Response = status + JSON
                        

                        

                          

                            
RequestPOST

                            

                              
1 · Start line
POST /api/v1/booking/search HTTP/1.1

                              
2 · Headers
Host: api.skynepal.local
Content-Type: application/json
Authorization: Bearer …

                              
3 · JSON body
{
  "origin": "KTM",
  "destination": "PKR",
  "departure_date": "2026-09-01",
  "adults": 1
}

                            

                          

                          
→

                          

                            
Response200

                            

                              
4 · Status
HTTP/1.1 200 OK

                              
5 · Headers
Content-Type: application/json

                              
6 · JSON body
{
  "items": [
    { "offer_id": "us-1", "price": 4500 }
  ]
}

                            

                          

                        

                        
This is what a REST POST API looks like: method + URL + headers + JSON body. GET usually has no body; POST carries data.

                      

                    


                    

                      

                        

                          

                            
SOAP message shape

                            

                              Envelope
                              
Outer wrapper — every SOAP call has one.

                              
<soap:Envelope xmlns:soap="…">
  …
</soap:Envelope>

                            

                            

                              Header (optional)
                              
Auth tokens, agency codes, tracing.

                              
<soap:Header>
  <Auth>…</Auth>
</soap:Header>

                            

                            

                              Body → operation
                              
The real method + fields (XML, not JSON).

                              
<soap:Body>
  <GetAvailability>
    <SectorFrom>KTM</SectorFrom>
    <SectorTo>PKR</SectorTo>
  </GetAvailability>
</soap:Body>

                            

                          

                          

                            

                              Still HTTP POST
                              
SOAP rides on POST to one endpoint URL.

                            

                            

                              SOAPAction
                              
Header names the operation (e.g. GetAvailability).

                            

                            

                              Content-Type
                              
Usually text/xml or application/soap+xml.

                            

                            

                              In this console
                              
Enable SOAP on a provider — the adapter builds the envelope from your mapping.

                            

                          

                        

                        
SOAP looks nested: Envelope → Header/Body → Method. Same idea as POST, different packaging (XML).

                      

                    


                    

                      

                        

                          

                            
REST POST JSON

                            
TransportHTTP POST

                            
FormatJSON object

                            
URLOften one path per action

                            
ActionEncoded in the path / method

                            
Looks likeClean key/value document

                            
POST /v1/search
Content-Type: application/json

{"origin":"KTM","destination":"PKR"}

                          

                          

                            
SOAP XML

                            
TransportAlso HTTP POST

                            
FormatXML envelope

                            
URLOften one shared endpoint

                            
ActionSOAPAction + body method

                            
Looks likeNested tags in a folder

                            
POST /Booking.asmx
SOAPAction: GetAvailability
Content-Type: text/xml

<soap:Envelope>…</soap:Envelope>

                          

                        

                        
Rule of thumb: if the body is {…} you’re in REST/JSON land; if you see <soap:Envelope>, you’re in SOAP land — both can be POST.
